Q1

Prove or Disprove — Asymptotic Notation

Thirteen claims comparing polynomial, logarithmic, and exponential growth. The pattern underneath all of them: exponentials beat every polynomial, and every polynomial beats every power of log — no exceptions, no matter the constants.

Core fact used throughout: for any constants \(a>1\) and \(c>0\): \(\lim_{n\to\infty} n^c / a^n = 0\). Polynomials lose to exponentials, always — the constants in the exponent (like /1000) only shift *when* the crossover happens, never *whether* it happens.
1a n³ = θ(2^(n/1000)) DISPROVE ▸

Exponential always beats polynomial in the long run: \(\lim_{n\to\infty} n^3/2^{n/1000} = 0\). That means \(n^3\) is strictly smaller order than \(2^{n/1000}\) — it's \(o(\cdot)\), a strict lower bound, not a tight \(\theta(\cdot)\) bound. θ requires the ratio to stay bounded both above and below by positive constants; here the ratio goes to zero, so the lower bound fails.

1b n³ = O(2^(n/1000)) PROVE ▸

Since \(n^3 = o(2^{n/1000})\) (shown in 1a), and little-o is a strictly stronger claim than big-O, it automatically implies \(O(\cdot)\) too. Anything that's eventually negligible compared to \(g(n)\) is certainly bounded above by it.

1c n³ = o(2^(n/1000)) PROVE ▸

Same limit computation as 1a: \(n^3/2^{n/1000} \to 0\), which is the exact definition of little-o. This is the strongest of the three claims in a/b/c, and the one that's actually true.

1d log³n = θ(n^(1/1000)) DISPROVE ▸

Any positive power of \(n\) — even a tiny one like \(n^{1/1000}\) — eventually outgrows any power of \(\log n\). So \(\log^3 n = o(n^{1/1000})\), a strict lower bound, which rules out the tight θ.

1e log³n = O(n^(1/1000)) PROVE ▸

Follows directly from little-o implying big-O, same as 1b.

1f log³n = o(n^(1/1000)) PROVE ▸

Direct application of "log grows slower than any positive polynomial power," no matter how small that exponent is.

1g n^(1/1000) = Ω(log³n) PROVE ▸

This is just 1f flipped. Since \(\log^3n = o(n^{1/1000})\), reversing the relationship gives \(n^{1/1000} = \omega(\log^3n)\), which is a stronger claim than — and therefore implies — \(\Omega(\log^3n)\).

1h n^(1/1000) = ω(log³n) PROVE ▸

Direct consequence of 1f — reversing a little-o relationship always gives a little-omega relationship.

1i 2^(n/1000) = Ω(n^99999) PROVE ▸

Exponential beats any fixed polynomial degree, however large. \(99999\) is just a big constant exponent — it doesn't change the category. The exponential eventually dominates.

1j 2^(n/1000) = ω(n^99999) PROVE ▸

Same reasoning as 1i, strict version — the ratio doesn't just stay bounded below, it grows without bound.

1k (n+a)^b = θ(n^b), b>0, a>1 PROVE ▸

Compute the ratio directly: \(\dfrac{(n+a)^b}{n^b} = \left(1+\dfrac{a}{n}\right)^b \to 1\) as \(n\to\infty\). A ratio converging to a positive constant means both an upper and lower bound exist — exactly what θ requires. Adding a constant \(a\) inside a polynomial never changes its asymptotic order.

1l (n+a)^b = O(n^b) PROVE ▸

Immediate from 1k — θ always implies both O and Ω individually.

1m (n+a)^b = Ω(n^b) PROVE ▸

Also immediate from 1k, the other half of the same θ bound.

Q2–4

Iterative, Divide-and-Conquer & Recursive Algorithms

Conceptual definitions — worth having crisp one-liners ready rather than vague descriptions.

Q2 Iterative algorithm DEFINE ▸

Repeats a block of steps using loops (for/while), maintaining state in variables that update each pass. No function calls itself — control stays in one stack frame.

Q3 Divide-and-conquer algorithm DEFINE ▸

Recursively breaks a problem into smaller subproblems of the same type, solves each (recursively), then combines results. Three steps: Divide, Conquer, Combine. Examples: Merge Sort, Quick Sort, Strassen's matrix multiplication.

Q5

Can Every Recursive Algorithm Become Iterative?

Q5 Theoretical conversion YES ▸

Yes, theoretically. Any recursion can be simulated iteratively using an explicit stack data structure to manually track the state the call stack would otherwise hold — push before what would be a recursive call, pop to resume where you left off, instead of call/return.

Q6

Strassen's Method

Q6 How Strassen reduced the running time EXPLAIN ▸
Baseline

Standard n×n matrix multiplication is Θ(n³) — 8 recursive multiplications of n/2×n/2 submatrices per level: \(T(n) = 8T(n/2) + \Theta(n^2)\).

The trick

Reduce from 8 multiplications to 7 per recursive level by cleverly combining sums/differences of submatrix blocks — trading extra additions (cheap) to save one multiplication (expensive) at every level of recursion.

Result

New recurrence: \(T(n) = 7T(n/2) + \Theta(n^2)\). By Master Theorem, \(a=7, b=2, \log_2 7 \approx 2.807\):

T(n) = Θ(n^log₂7) ≈ Θ(n^2.81)

Beats the naive Θ(n³) — a real, if modest, asymptotic win.

Hire-Assistant Problem — Probability

n candidates interviewed in random order; you "hire" whenever the current candidate beats everyone seen so far. Candidate 1 is always hired; the last hire is always the overall best.

a P(hire exactly 1 candidate), n=10 1/n ▸

Hiring only candidate 1 means every candidate after them (2 through 10) must be worse — i.e. candidate 1 is the best of all 10. Probability the overall best lands in position 1, uniformly random order:

P(exactly 1 hire) = 1/10
b P(hire all 10 candidates) 1/n! ▸

Every candidate must beat all before them — the sequence must arrive in strictly increasing order of quality. Only 1 of 10! orderings does this:

P(hire all 10) = 1/10! = 1/3,628,800
c P(hire exactly 2 candidates) H(n-1)/n ▸

Candidate 1 is always hired. Exactly one more hire means exactly one "record-breaking" candidate appears in positions 2–10, and — since it's the last hire — it must be the overall maximum. Using indicator random variables \(X_i\), the expected number of hires is \(E[\#\text{hires}] = \sum_{i=1}^n \frac{1}{i} = H_n\).

The exact count of permutations with exactly 2 records relates to the unsigned Stirling numbers of the first kind:

P(exactly 2 hires for n) = H(n−1) / n

For n=10: \(H_9 = 1+\frac12+\frac13+\cdots+\frac19 \approx 2.828968\)

P(exactly 2 hires) = H₉/10 ≈ 0.2829
d General formula for n candidates SUMMARY ▸

Q10

Permute-By-Sorting2 — Handling Duplicate Priorities

Q10 Fix the tie-breaking problem DESIGN ▸
The problem

Standard PERMUTE-BY-SORTING assigns each element a random priority P[i] (e.g. from 1 to n³) and sorts by priority. If priorities can tie, the sort's tie-breaking isn't random — it breaks uniformity of the resulting permutation.

The fix
PERMUTE-BY-SORTING2(A):
1  n = A.length
2  let P[1..n] be a new array
3  for i = 1 to n:
4      P[i] = RANDOM(1, n^3)       // priority, may collide
5  sort A, using P as sort keys, and break ties by
   recursively re-randomizing ONLY the tied elements
   with fresh priorities until all priorities among
   ties are distinct
6  return A
Simpler equivalent

Use P[i] = (RANDOM(1, n³), i) — pair each random priority with the original index. Since indices are always distinct, ties in the composite key are impossible, and the sort is a valid uniform random permutation. This is the standard practical fix: pair with a unique tiebreaker rather than looping.

Q11 T(n) = 2T(n/2) + Dn Case 2 ▸

a=2, b=2, \(n^{\log_2 2} = n^1\). \(f(n)=Dn=\Theta(n^1)\) → Case 2.

T(n) = Θ(n log n)
Q12 T(n) = 2T(n−1) + D Unroll ▸

Subtracts rather than divides — not a Master Theorem case. Solve by unrolling:

\(T(n) = 2T(n-1)+D = 2[2T(n-2)+D]+D = 4T(n-2)+2D+D = \ldots = 2^{n-1}T(1) + D(2^{n-1}+\ldots+2+1) = 2^{n-1}C + D(2^n-1)\)

T(n) = Θ(2ⁿ)
Q13 T(n) = T(n−1) + D log n Unroll ▸

Unroll: \(T(n) = C + D\sum_{k=2}^{n} \log k = C + D\log(n!) = \Theta(Dn\log n)\) since \(\log(n!) = \Theta(n\log n)\) by Stirling's approximation.

T(n) = Θ(n log n)
Q14 T(n) = T(n−2) + Dn² Unroll ▸

Unroll over n/2 steps: \(T(n) = C + D(n^2 + (n-2)^2 + (n-4)^2 + \ldots)\) — dominated by the top term, sum of n/2 terms each Θ(n²):

T(n) = Θ(n³)
Q15 T(n) = 4T(n/3) + Dn log n Case 1 ▸

a=4, b=3, \(n^{\log_3 4} \approx n^{1.26}\). \(f(n) = Dn\log n\) grows slower than \(n^{1.26}\) since 1.26 > 1 → Case 1.

T(n) = Θ(n^log₃4) ≈ Θ(n^1.26)
Q16 T(n) = 3T(n/5) + n/log n Case 3 ▸

a=3, b=5, \(n^{\log_5 3} \approx n^{0.68}\). \(f(n)=n/\log n\) grows faster than \(n^{0.68}\) → check the regularity condition: \(af(n/b) = 3\cdot\frac{n/5}{\log(n/5)} \approx \frac{3}{5}\cdot\frac{n}{\log n} \leq c\cdot\frac{n}{\log n}\) for \(c=3/5<1\) ✓ → Case 3.

T(n) = Θ(n/log n)
Q17 T(n) = 7T(n/2) + Dn²√n Case 1 ▸

a=7, b=2, \(n^{\log_2 7} \approx n^{2.807}\). \(f(n)=Dn^{2.5}\), and 2.5 < 2.807 → Case 1.

T(n) = Θ(n^log₂7) ≈ Θ(n^2.81)
Q18 T(n) = 9T(n/3−2) + Dn/2 Case 1 ▸

Treat n/3−2 ≈ n/3 for large n (standard simplification). a=9, b=3, \(n^{\log_3 9} = n^2\). \(f(n)=Dn/2=\Theta(n)\), and \(n = O(n^{2-\epsilon})\) → Case 1.

T(n) = Θ(n²)

Unroll: \(T(n) = C + (n + (n-1) + \ldots + 2) = C + \left[\frac{n(n+1)}{2}-1\right] = \Theta(n^2)\)

T(n) = Θ(n²)

Q21 Increasing vs. decreasing input Θ(n log n) either way ▸
Increasing-order input

BUILD-MAX-HEAP still takes Θ(n) — the heap property is violated maximally, since the smallest elements sit at the top of an increasing array, so heapify does full work. Then n−1 EXTRACT-MAX calls, each O(log n).

Θ(n log n) — same as worst case
Decreasing-order input

The array is already a valid max-heap (root is largest, decreasing satisfies the heap property). BUILD-MAX-HEAP takes Θ(n) trivially — no swaps needed. But EXTRACT-MAX must still remove and re-heapify n−1 times, each still O(log n) in the worst case.

Θ(n log n) — extraction still destroys structure each time

Q23

Merge K Sorted Lists in O(n log k)

Q23 K-way merge with a min-heap DESIGN ▸ 
MERGE-K-LISTS(lists[1..k]):
1  build a min-heap H
2  for i = 1 to k:
3      if lists[i] is not empty:
4          insert (lists[i][0], i, 0) into H    // (value, list index, position index)
5  result = empty list
6  while H is not empty:
7      (val, i, pos) = EXTRACT-MIN(H)
8      append val to result
9      if pos+1 < length(lists[i]):
10         insert (lists[i][pos+1], i, pos+1) into H
11 return result

Analysis: the heap never holds more than k elements → each insert/extract is O(log k). Total n elements processed, each with one insert + one extract:

O(n log k)
Q24

D-ary Heap

Like a binary heap, but non-leaf nodes have d children instead of 2.

a Array representation FORMULA ▸

For a node at index i (1-indexed):

Parent: ⌊(i−2)/d⌋ + 1
j-th child (1 ≤ j ≤ d): d(i−1) + j + 1
b Height in terms of n and d FORMULA ▸

Each level multiplies capacity by d, so height h satisfies \(d^h \approx n\):

h = ⌊log_d n⌋ = Θ(log n / log d)
c EXTRACT-MAX in a d-ary max-heap DESIGN ▸ 
D-EXTRACT-MAX(A, d):
1  max = A[1]
2  A[1] = A[heap-size]
3  heap-size = heap-size - 1
4  D-MAX-HEAPIFY(A, 1, d)
5  return max

D-MAX-HEAPIFY(A, i, d):
1  largest = i
2  for j = 1 to d:
3      child = d*(i-1) + j + 1
4      if child ≤ heap-size and A[child] > A[largest]:
5          largest = child
6  if largest ≠ i:
7      swap A[i], A[largest]
8      D-MAX-HEAPIFY(A, largest, d)

Running time: O(d log_d n) — each level does O(d) work comparing children, tree has O(log_d n) levels.

d INSERT in a d-ary max-heap DESIGN ▸ 
D-INSERT(A, key, d):
1  heap-size = heap-size + 1
2  A[heap-size] = key
3  i = heap-size
4  while i > 1 and A[PARENT(i,d)] < A[i]:
5      swap A[i], A[PARENT(i,d)]
6      i = PARENT(i,d)

Running time: O(log_d n) — a single path up the tree.

Q25 Two applications EXPLAIN ▸
Priority queue

A max-heap directly implements a priority queue where "priority" = key value.

Event scheduler in a simulator

Use a min-heap keyed on event time. To advance simulation: EXTRACT-MIN() pulls the next chronological event in O(log n). New events (possibly triggered by processing the current one) are INSERTed in O(log n). This avoids re-sorting the entire event list after every insertion — the classic use case for a min-heap.

Q26

Quicksort + Insertion Sort Hybrid

Q26 Stop quicksort early, finish with insertion sort WORKS ▸

Yes, this approach works.

Why it works

Quicksort's recursion is stopped early — subarrays under size k are left unsorted, just "roughly in the right region," since quicksort still partitions around pivots and correctly places large-scale order. The array ends up "almost sorted" — each element is at most k positions from its final sorted position. Insertion sort is Θ(n·d) where d = max distance any element is from its correct place — with d ≤ k, insertion sort finishes in O(nk).

Running time
O(nk + n log(n/k))

The nk term is the final insertion-sort pass; n log(n/k) is the quicksort recursion, which now only descends to subarrays of size k — stopping k early cuts off the bottom log k levels of recursion.

How to pick k
ContextChoice
In theoryk = Θ(log n) — balances nk against n log(n/k), preserving overall Θ(n log n)
In practicek ≈ 5–20, chosen empirically via benchmarking on the actual machine/compiler
Q27–28

Open Addressing vs. Chaining

Q27 Open addressing EXPLAIN ▸

All elements are stored directly in the hash table array itself — no external lists. On collision, probe a sequence of alternative slots (linear, quadratic, or double hashing) until an empty slot is found. Load factor \(\alpha \leq 1\) always — it can never exceed table size. Deletion is tricky: must use a "DELETED" marker rather than simply clearing the slot, or later searches for elements probed past the cleared slot will incorrectly terminate early.

Q28 Chaining EXPLAIN ▸

Each table slot holds a linked list (chain) of all elements hashing to that slot. Load factor \(\alpha = n/m\) can exceed 1. Simple to implement — deletion is standard linked-list deletion. Expected search time under simple uniform hashing:

Θ(1 + α)
Q29

GCD Recurrence — Euclid's Algorithm

Q29 Recurrence and running time SOLVE ▸ 
GCD(m, n):
  if m mod n == 0:
      return n
  else:
      return GCD(n, m mod n)
A. The recurrence

The recursive call replaces (m, n) with (n, m mod n). The standard textbook framing (CLRS-style) expresses running time as:

T(n) = T(m mod n) + O(1)

Or, using the worst-case per-step bound (consecutive Fibonacci numbers trigger the most recursive calls before reaching remainder 0):

T(n) = T(n−1) + O(1)  (worst-case bound)
B. Solving it

GCD's worst case occurs on consecutive Fibonacci numbers — the number of recursive calls k before termination satisfies \(n \geq \text{Fib}(k) \approx \varphi^k/\sqrt5\), so \(k = O(\log n)\). Each recursive call does O(1) work (one mod operation) outside the recursive call itself:

T(n) = Θ(log n)

(More precisely: O(log n) calls. If the cost of the mod operation on very large numbers is counted as non-constant, multiply by cost-per-mod — but for the standard CS-course treatment, T(n) = Θ(log n) is the expected answer.)

Q30

Hash Authentication — Adversary Success Probability

Q30 Universal hashing for message authentication SOLVE ▸

This is the universal hashing collision bound applied to authentication (a Wegman–Carter MAC).

Setup

Adversary intercepts (m, t) with t = h(m), and wants to forge (m', t') with m' ≠ m such that t' = h(m'), without knowing which \(h \in H\) was secretly chosen.

Reasoning

Since h maps to \(\mathbb{Z}_p\) and H is a universal family, for any fixed pair of distinct messages \(m \neq m'\), the number of \(h \in H\) for which \(h(m)=h(m')\) is at most \(|H|/p\) — exactly the universal hashing collision property (\(\Pr[h(k)=h(l)] \leq 1/m\)), here with p in place of m.

The adversary doesn't need \(h(m')=h(m)\) — they've observed \(t=h(m)\) and just need to guess \(t'=h(m')\) correctly for the same secret h. With no information narrowing down which specific h was picked beyond the one observed pair, and t' must land on exactly one of p possible tag values:

P(adversary succeeds) ≤ 1/p

This holds regardless of the adversary's computational power — the entire point of universal hashing for authentication: security depends only on the size of the tag space p, not on computational hardness assumptions.

BST Search Sequences — Which Is Impossible

Searching for 363 in a BST with values 1–1000. A valid sequence must monotonically converge toward 363 — each step must stay within the bound established by every prior step, since going left/right at a node bounds every subsequent value in that subtree.

a 924, 220, 911, 244, 898, 258, 362, 363 INVALID ▸

925 → 202 (<363, go left, bound <925 tightens to <202) → 911: same problem — after visiting 202, 911 exceeds the upper bound of 202.

c 2, 399, 387, 219, 266, 382, 381, 278, 363 VALID ▸

Trace the tightening bound (lo, hi) at each step:

2<363, go rightbound >2
399>363, go leftbound (2, 399)
387>363, go leftbound (2, 387)
219<363, go rightbound (219, 387)

Q32

O(V) Simple Cycle Detection — Undirected Graph

Q32 DFS with back-edge detection DESIGN ▸ 
HAS-SIMPLE-CYCLE(G):
1  color[v] = WHITE for all v ∈ G.V
2  for each vertex u ∈ G.V:
3      if color[u] == WHITE:
4          if DFS-VISIT-CYCLE(u, NIL) == TRUE:
5              return TRUE
6  return FALSE

DFS-VISIT-CYCLE(u, parent):
1  color[u] = GRAY
2  for each v ∈ G.Adj[u]:
3      if v == parent:
4          continue                          // skip the edge we just came from
5      if color[v] == GRAY:
6          return TRUE                       // back edge found → cycle
7      if color[v] == WHITE:
8          if DFS-VISIT-CYCLE(v, u) == TRUE:
9              return TRUE
10 color[u] = BLACK
11 return FALSE
Correctness

In an undirected graph, DFS finds a cycle if and only if it encounters a "back edge" — an edge to an already-visited (GRAY, currently on the recursion stack) vertex that is not the immediate parent. The edge to the parent is the same undirected edge just traversed, not a real cycle, so it must be explicitly skipped.

Running time — why O(V), not O(V+E)

Standard DFS is O(V+E), but here we only check for the existence of any cycle: if the graph has no cycle, it's a forest, so E ≤ V−1 — DFS visits O(V) vertices and O(E) ≤ O(V) edges in that case. If a cycle is found, we return immediately upon detecting the first back edge, without exploring the rest of the graph. Either way, total work is:

O(V)
Q33

Tree Diameter in O(V+E)

Q33 Two-BFS technique DESIGN ▸ 
TREE-DIAMETER(T):
1  pick any vertex s ∈ T.V
2  (u, dist_u) = BFS-FARTHEST(T, s)      // find farthest vertex from s
3  (v, dist_v) = BFS-FARTHEST(T, u)      // find farthest vertex from u
4  return dist_v                          // this is the diameter

BFS-FARTHEST(T, start):
1  run BFS from start, computing dist[x] for all x ∈ T.V
2  let f = vertex maximizing dist[f]

Correctness — why any starting point works

In a tree, running BFS from any starting vertex s and finding the farthest vertex u from it guarantees u is one endpoint of some longest path (diameter path) in the tree. Running BFS again from u finds v, the true farthest vertex from u — and (u, v) is guaranteed to be a diameter-achieving pair. This is a well-known tree property, provable by contradiction: if u weren't a diameter endpoint, a longer path could be found, contradicting u being farthest from s.

Running time

Two BFS calls, each O(V+E). Since it's a tree, E = V−1, so total is:

O(V+E) = O(V)
